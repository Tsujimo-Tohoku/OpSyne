# ADR 0001: 本体と独立して開発するDiscordアダプタ

- 状態: 初期分離段階の記録。本体接続に関する記述は[ADR 0007](../../../docs/adr/0007-discord-bridge.md)で更新。
- 日付: 2026-09-15
- 対象: `apps/discord_bot/` 内の配置、依存、永続化、信頼境界

## 背景

ユーザーは本体を別のCodexタスクで開発中であり、その作業を妨げずBotを並行実装することを求めた。本体のAPI・契約も変更中のため、共有ファイルや環境を同時編集すると競合しやすい。

## 決定

同じリポジトリの `apps/discord_bot/` を独立したPythonプロジェクトとする。このディレクトリに依存定義、`uv.lock`、`.venv`、キャッシュ、設定例、テスト、文書を置く。本体の `opsyne` パッケージをimportせず、本体の依存定義・lock・仮想環境・起動処理を変更しない。`dev.py` はBot専用の作業ディレクトリと環境を設定する。既存のuv実行ファイルは読み取り利用できる。

Botは別プロセスで起動する。製品との通信は明示的なHTTP接続に限定し、Control DB、実行用資格情報、署名秘密鍵、Runnerへ直接接続しない。フォルダ分離は実行時の権限分離を保証しないため、配備時にプロセス、資格情報、保存先、通信許可をそれぞれ設定する。

### 保存する情報の正本

| 保存先 | Botが管理する内容 | 管理しない内容 |
|---|---|---|
| `outbox.sqlite3` | 通知ID、送信先、表示用スナップショット、配送状態、DiscordメッセージID | 製品の案件・承認・操作台帳 |
| `receipts.sqlite3` | Interaction ID、原文のハッシュ、返答の再表示用データ | 承認の成立、実行許可、Discord Interactionトークン |
| Control側の永続ストア | 将来のbridgeが案件、固定計画、承認、権限、処理結果を照合する正本 | このBotでの新規実装対象には含めない |

Botの受領記録とControlの承認記録は別物である。Controlへの応答が失われた場合、Botは受付結果不明と表示し、承認要求を自動再送しない。配送中の停止・送信結果不明も `UNKNOWN` として残し、照合なしで通知を再送しない。

### 通知と承認の境界

通知受付とDiscord配送はBot内で実装する。本体の案件更新とBotの通知待ち保存は、現在は同じトランザクションになっていない。本体の送信待ちと安定した通知IDを用いる接続は、別の統合作業として扱う。

承認窓口には [Control bridge提案](control-bridge.md) を用いる。未設定時は承認・実行を行わない。Discordの署名付き入力をbridgeへ渡し、本人の対応付け、固定計画の再表示、短命な確認ID、承認の永続化と重複排除はControl側の責任とする。Botのロール指定や管理者資格情報で人の承認を代行しない。

承認後もControlが現在条件で認可し、Runnerが実行し、独立した結果確認へ進む。Botの表示や成功応答だけで案件を解決しない。

## 代替案と影響

- 本体のパッケージ・環境に追加する案は、同時編集を避ける今回の要件に合わない。
- 別リポジトリも可能だが、現時点では配置・依存・プロセスの独立で並行開発できる。移動しやすい構成を保つ。
- 表示モデルは本体と重複するため、統合時に明示的な変換と契約試験が必要になる。

この決定は、本体APIの完成、本番配備、実Discord接続の検証済みを意味しない。これらの接続確認はBot単体のローカル試験から分ける。
