# サービスを選択して操作する

ログイン後のサービス一覧から保守対象を開くと、左メニューの5項目をそのサービスに限定して使えます。新規追加後も登録したサービスのホームへ進みます。GitHub連携は不要です。

| メニュー | 内容 |
| --- | --- |
| ホーム | ログ受信状況、未解決インシデント・承認待ちの件数、次にすること |
| インシデント | 調査・対応が必要な問題。詳細では概要と対応案、ログと調査、対応履歴・復旧確認を切り替え |
| 承認待ち | 対応案とログの解析ルール。自身が提案・編集したものは別の承認者を待つ |
| 操作履歴 | 提案・承認・実行・復旧確認と、その時点の記録 |
| 設定 | このサービスのログ接続・解析ルール・復旧操作・確認方法と、全体共通設定の表示 |

左上でサービスを切り替えても同じメニューを維持します。詳細からの切り替えは移動先のインシデント一覧へ進みます。「← サービス一覧」で全体へ戻ります。390px幅ではメニューが上部に並び、キーボードでも移動できます。

`#services/orders/approvals` のようにURLにサービスIDを保持します。詳細URLの例は `#services/orders/incidents/INC-001`。直接開く、再読み込み、戻る／進むでも同じ対象を表示します。以前の対象を含まないURLは一覧への案内になります。

## 件数と取得状態

件数と一覧には [サービス別API](service-api.md) を使用します。50件を超える一覧は「一部取得」と総件数を表示し、「続きを取得」で追加表示します。読み込み済みの続きを保持している間、一覧の再取得は右上の「更新」で行います。途中で一覧が変わってカーソルが失効した場合は先頭から読み直します。

取得失敗を0件と表示しません。ログ未受信・機能の状態未確認・検知されたインシデントを区別します。サービス一覧とホームでは、現在のAPIから機能の正常性を確定できないため「未確認」と表示します。操作の `SUCCEEDED` と復旧確認の `PASS` は別項目です。`UNKNOWN` は確認がPASSでも操作成功にはなりません。

## 承認・実行の途中で移動したとき

対象や認証主体を切り替えると確認画面を閉じ、切り替え前の通信結果を新しい画面に反映しません。承認待ちの応答を受け取る前に移動した場合、続く実行要求は送りません。既に送った操作は取り消せないため、対象サービスへ戻ってインシデントと実行記録を確認します。操作を自動再送しません。

## 全体共通の情報

AI接続・日次上限・自動提案・認証は全サービス共通です。サービス一覧から共通・所属不明の操作履歴へ移動できます。管理者向けの復元・実行保留の管理もサービス一覧にあります。サービスを切り替えても権限は増えません。

## ブラウザ検証

通常のPython検査とは別に、インストール済みのPlaywrightとEdgeを使います。`NODE_PATH` は `playwright/test` を解決できるディレクトリに設定してください。APIキーを設定せず、未使用のデータ領域でサーバーを起動します。

```text
python scripts/dev.py run --locked python -m opsyne serve --data-dir .local/navigation-test --port 8780
node scripts/test_service_navigation.cjs http://127.0.0.1:8780 .local/navigation-test
```

試験はその専用環境に合成デモと会員サービスを登録します。実APIでのサービス分離・登録・URL遷移に加え、ブラウザで応答を模擬し、取得上限・409・取得失敗・遅延・承認中の切り替え・UNKNOWNを確認します。実サービスと実LLMへ通信しません。成功時の画面と結果は指定データ領域の `browser-results/` に保存します。

既存の承認画面の回帰確認には、別々の新規データ領域で `scripts/test_recovery_ui.cjs` と `scripts/test_adapter_review_ui.cjs` を使います。

Issue #9の「利用者が現在の対象と次の操作を説明できるか」の確認は未実施です。ブラウザ自動試験から使いやすさの評価まで完了したとは判断しません。
