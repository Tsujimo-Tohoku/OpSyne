# ADR 0002: 単一ホストのローカル製品

- 日付: 2026-09-15
- 状態: 採用（ローカル v0.1）
- 対応: 設計原文 §2–10。[ADR 0001](0001-development-foundation.md)で未決だった初期実行構成を具体化。

## 決定

1. **保存**: 標準SQLiteを使用し、Control、Collector、Runner、合成デモのDBを分ける。WAL、同期設定FULL、明示的トランザクションで、原本・受領・取得位置・案件・承認・実行意図を永続化する。検索専用サーバーは導入せず、SQLiteへの範囲・件数を制限した問い合わせを使う。
2. **処理待ち**: 外部キューを導入せず、永続化した未配送イベント・有限taskと、同一プロセス内の収集／調査ワーカーを使う。LLM停止中も収集を継続する。再解析は全原本の分割走査で行い、新規配送をackせず、検知や対象操作を再発火しない。
3. **APIとUI**: FastAPI/Uvicornをlocalhostに起動し、同梱のHTML/CSS/JavaScript画面を提供する。役割別Bearerトークンをローカル生成し、同一オリジンと認証を確認する。
4. **LLM**: OpenAI Python SDKとユーザー指定の `gpt-5.6-luna` を使用。Responses APIの構造化出力、`store=False`、最大2500出力トークン、30秒タイムアウト、自動リトライなし。許可済み証拠だけをマスク・制限して渡し、Toolを公開しない。通常調査とAdapter Agentの変換提案を分け、後者も承認待ちに留める。
5. **承認と操作**: 固定した計画digest、対象実体・版、能力版、期限、承認世代を照合し、最長30秒のHMAC署名付き許可を発行する。提案者本人の承認を拒否し、実行前の意図をRunnerに保存する。結果不明は `UNKNOWN` とし、対象単位の未確定予約を維持する。
6. **Connector**: 合成デモと、管理者が登録した固定HTTP操作・独立GET確認を提供する。操作の引数や接続先をAgentが自由に作り替える経路は設けない。汎用HTTPには正本となる操作履歴照合APIがないため、`UNKNOWN` の自動解消・再送を行わない。
7. **復元**: 停止・単一起動ロック下でDBと鍵・トークンを一式バックアップする。復元先は新しいディレクトリにし、途中停止は `restore.pending` で起動拒否する。復元完了時に認可世代を更新して実行許可の発行を保留する。管理者が外部操作履歴と台帳を照合した記録を残してから保留を解除する。

## 代替案と影響

PostgreSQL、オブジェクトストレージ、外部キュー、OIDC、複数プロセス配備は、規模と脅威モデルを確認する次段階へ残す。これによりローカル導入を単純にできる一方、高可用性・分散トランザクション・検索性能・組織単位の権限制御は提供しない。

`storage` は業務判断を持たない共通保存機構とする。`runtime.py` と `api` / CLIが各領域を結線し、業務領域同士は直接importしない。`contracts` はI/Oと業務実装に依存しない。

同一所有者のプロセスはDB・ファイル・環境変数へアクセスできる。別DB、Gateway、役割別トークンはOSやネットワークの隔離ではなく、単一所有者が全トークンを保持できるため、独立した人間の本人確認を保証しない。LLM入力マスクも完全な機密分類ではない。

独立GETの成功は登録条件の成立を示す。業務全体の復旧やSOC上の侵害根絶を一般化して証明するものではない。複数工程の補償操作、統計・時系列相関、別障害領域監視、保持期限・削除、接続先固有の結果照合は今後の拡張対象とする。

## 検証方針

一時SQLiteでクラッシュ・競合・期限切れ・改変・越権・復元を検査し、HTTP/OpenAIは模擬応答で要求と拒否経路を検査する。UIの操作確認と品質検査は実施した範囲を別途報告する。実APIキーを使う疎通や、本番接続・負荷・障害訓練はこのADRの採用だけでは完了扱いにしない。
