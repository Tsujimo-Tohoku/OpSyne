# ADR 0001: Python + uv の開発基盤

- 日付: 2026-09-15
- 状態: 採用（本格実装前の開発環境）

## 背景

OpSyneの設計原文は責任分離と不変条件を定めていますが、開発言語、DB、API、配備製品は指定していません。
今回の依頼は、新規作業先にAGENTS.md等の開発環境を用意することです。Python + uvはユーザーの選択です。

## 決定

- Python 3.12系を最初の検証対象にします。既存の参考環境と互換性があり、手元の3.12.14を利用できます。
- 単一の `src/opsyne` パッケージで開始し、責務をサブパッケージで分離します。独立配備と資格情報分離は別途設計します。
- uvで開発環境とlockを管理し、Ruff / mypy strict / import-linter / pytestを共通スクリプトで実行します。
- Hatchlingでwheel/sdistを作成します。バックエンドもlockに含め、同期した環境でビルドします。
- 初回の分離ビルドにもHatchlingと依存の版制約を指定し、初期同期時のビルド依存解決を固定します。
- 実行時依存はゼロから開始します。Web・永続化・LLMの依存は必要な段階で決定します。
- ルートAGENTS.mdに共通ルールを集約します。現段階で大量の階層別ルールやCodex固有のグローバル設定は追加しません。
- GitHub ActionsはWindowsとLinuxの検査定義のみ用意します。

## 代替案と影響

- requirements.txtだけの管理より、pyprojectとuv.lockで開発・ビルド依存まで一元化します。uvの導入と更新管理が必要になります。
- 初期から多数のサービスやDBを起動すると、未決定の配備・保存方式が固定されます。契約と障害時の意味を決めてから追加します。
- 複数Python版のサポートは今後拡張できます。対応範囲を広げる際はCIと依存の互換性を検証します。
- import検査は静的な依存のみ検証します。動的呼び出し、権限、ネットワークの制限には別の試験が必要です。
