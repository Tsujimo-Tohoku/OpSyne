# ADR 0007: 独立DiscordアダプタとControl内の承認・通知履歴

- 状態: 採用
- 対象: 単一ホスト・単一所有者向けv0.1

## 決定

Botは `apps/discord_bot` に独立した依存・環境・状態を持ち、本体の専用HTTP APIへ接続する。
Botへ本体ログイントークン、Control DB、Runnerの操作資格情報を渡さない。
本体の接続設定は所有者が管理するJSONファイルで明示し、環境変数
`OPSYNE_DISCORD_CONFIG` を指定した場合だけAPIを登録する。

Discord User IDを既存 `tokens.json` のactorに対応付ける。Discordのロール名・表示名や
Botが主張するactorは認可に使わない。各要求で設定ファイルと現在のactorを読み直す。
本人対応は所有者による事前登録であり、OAuthによる自動本人確認・組織認証ではない。
同一人物へ提案者・承認者の別名を割り当てて自己承認制限を回避しない。

本体でも元の署名バイト列と時刻・アプリ・guild・channel・利用者を検証する。
PyNaClを依存追加し、Botと同じEd25519検証方式を使う。署名原文・Interaction tokenは保存しない。

確認ボタンは120秒以内、計画ID・digest・本人・channel・設定fingerprint・権限世代に結合する。
承認、確認ボタンの消費、Interaction受付結果、監査を同じControl SQLiteトランザクションで保存する。
通常APIの承認処理を同一ドメイン内のトランザクション用メソッドへ抽出し、同じ検証を利用する。
実行許可・実行台帳・独立確認の既存経路は維持する。Botから実行は開始しない。

## 公開契約と表示

- `POST /api/discord/interactions`: 署名原文を専用Bearer tokenで中継。
- `GET /api/discord/notifications?cursor=...`: 許可サービスの案件更新だけを取得。
- 操作は案件・計画照会、計画確認、確認済み計画の承認、差し戻しに限定する。
- 本体Planには版番号がない。IDとdigestで固定内容を識別し、既存Botの `version=1` は
  **表示形式の版**と定義する。画面ラベルも変更し、対象の版と混同しない。
- PlanViewに省略可能な `state` / `approver` を追加。DRAFT以外では操作ボタンを出さない。
- 通知・案件照会には原本、ログ由来タイトル、LLM文章を含めない。
- 計画は理由・提案者・根拠参照・操作版・影響・確認条件を表示する。
  capabilityパラメータやcheck設定を含むため、サービスごとに
  `disclose_plan_details=true` を明示した場合だけ開示する。表示しきれない計画は本体で確認する。

## 耐久性と制約

案件更新と通知イベントを同一トランザクションで保存する。Botはローカルoutboxに全件保存してから
カーソルを進める。途中停止は固定event_idによる再取込に収束し、送信結果UNKNOWNを再送しない。
通知は導入後に発生した案件更新から始まる。導入前の全案件を自動再通知しない。

設定・承認世代変更や復元でカーソルが無効になった場合、同期を停止する。所有者が履歴を照合し、
既存outboxを保持して `reset-feed-cursor` を実施する。配送先変更により同じイベントの内容が
変わる場合は競合として停止し、黙って再送しない。

Controlの3テーブルは既存DBバックアップ対象となる。接続設定とBotの状態は別途保管する。
履歴の自動削除、複数組織、ロール同期、案件スレッド、既存投稿編集、常駐サービス管理は未対応。
本体はループバック専用のまま、外部公開はBotの `/interactions` に限定する。
