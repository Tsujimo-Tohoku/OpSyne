# ADR 0003: 未知形式から変換案を自動生成する

日付: 2026-09-15。状態: 採用。設計書 §5.2・§6–7、利用者の自動提案の依頼に対応。

## 背景

初期実装は案件ごとの手動依頼からAdapter Agentを起動していた。未知形式の発見後にも操作が必要で、同じ形式の多数のログが別案件になっていた。未知を検知したプログラムから案の生成までを自動化し、固定定義の検証・承認という境界を維持する。

## 決定

- 新規取込の未知解釈を、観測源・サービス・実体・版と、キー／型から作るJSON構造の指紋で集約する。通常の値は捨て、明示的な形式・スキーマ・イベント種別の値はハッシュで区別する。原本はCollectorに保持し、指紋を意味の正しさや権限と扱わない。
- Controlにグループ、重複排除用の原本参照、件数、最新20件の標本、task・案・試行状態を永続化する。案件には同形式の証拠を追加する。task作成時の標本と対象版は固定し、案件表示の最新100件から外れても永続した証拠所属で権限を検査する。
- 既定で自動提案を有効にし、APIキー設定時に最初の検出から5秒後に予約する。収集ワーカーはLLMを呼ばず、有限taskを調査ワーカーが実行する。既存の通常調査と日次予算を共有する。
- LLM提案を原本標本と照合し、全標本が少なくとも一部解釈できること、対象版が現行であること、承認済み定義と適用範囲が重ならないことを確認してからDRAFTを保存する。機械検査は業務的な意味の保証ではなく、別主体による承認が有効化の条件である。
- 生成中・承認待ちの重複予約を抑える。失敗・保留後の自動再試行は900秒以上の待機と新規証拠を必要とし、グループごとの既定上限は3回。結果不明の同じ要求を無条件に再送しない。手動再提案はこの待機／回数制限を越えられるが、実行中の重複と日次予算は共通制御する。
- 送信前に日次上限・期限で停止したtaskは、グループの試行数を戻す。未送信と確認できるため新規証拠を必須とせず、日次上限なら翌UTC日かつ待機時間の経過後、期限切れなら待機時間の経過後に再予約する。自動生成オフ・キー未設定では未開始の自動taskの送信も保留する。
- 非JSON・曖昧または過大な入力は自動生成対象外として理由を表示する。再解析はこの検出・予約経路を通らず、原本からの解釈更新だけを行う。

## 影響と制約

新規SQLiteテーブルは起動時に追加し、既存taskの新しい範囲指定フィールドは省略可能にする。既存の処理済みログへ一斉に有料提案を予約する移行は行わず、必要な案件で手動依頼を使える。

構造の集約は形式推定であり、同構造で値の意味が異なるすべてのログを識別できない。標本は最大20件、LLMへの送信はマスク後の合計12000文字に制限する。未知の値を成功へ補完しない。承認済み定義と重なる改善は、利用者が対象と意味を確認して既存版を管理する。

全ログを個別にLLMへ送る方式は費用と重複を増やすため採用しない。生成案の無承認での有効化も採用しない。
