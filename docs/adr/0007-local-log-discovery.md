# ADR 0007: 既存読取権限でのローカルログ探索

- 状態: 採用
- 関連: [作業宣言 #15](https://github.com/siro103/OpSyne/issues/15)

## 背景

利用者はアプリの配置場所を知っていても、基本監視に使うログのファイル名や出力先を把握していないことがある。アプリ内だけを探すと、設定に書かれた別ディレクトリのログを見落とす。

## 決定

Collector に、副作用のない `discover_logs` を追加する。CLI と API が呼び出し、共有する要求・結果型は contracts に置く。API は既存の観測源登録と同じ admin 認証を要求する。OS の現在の読取権限を使い、新規資格情報や LLM は使用しない。探索結果を保存する DB は追加しない。

`POST /api/log-discovery` は `{"roots":["/opt/app"]}` を受け取り、候補と探索状態を返す。同一アプリプロセス内では同時に一件だけ処理する。探索中の再要求は 409。認証なしは 401、admin 以外は 403。ファイルの状態確認とサンプル読み取りは、監視の収集ロックを保持せず FastAPI の同期ハンドラーで行う。結果は `no-store`。

指定フォルダー配下を横断し、対応する設定のリテラルな出力先を追加探索する。相対出力先は、設定ファイルの親と指定した各アプリフォルダーを基準に存在する候補を確認する。複数存在する場合は複数候補として返す。GitHub、SSH、環境変数展開、シェル、設定内のコード実行、外部 API 呼び出しは行わない。

結果の `signals` は、末尾サンプル内に HTTP アクセス・エラー・起動停止に相当する記述を見つけたというヒントである。サービスへの帰属、監視の設定完了、現在の正常性は保証しない。画面では選択したパスを既存登録欄へ入力し、ユーザーの登録操作を待つ。変換定義の承認や既存の正常性判定を代替しない。

## 上限と対象外

- 一要求の起点は最大 8、ファイル・ディレクトリの確認は最大 10,000、深さ 24、候補 100、設定参照 64。
- ログ末尾は一ファイル 16 KiB、設定先頭は 64 KiB、総読取量は 4 MiB。
- 10 秒を目安にファイルシステム操作の間で停止する。OS のブロッキング I/O を強制中断する期限ではない。ローカルにマウントされた遠隔ファイルシステムを自動判別するものではない。
- シンボリックリンク・Windows ジャンクションなどの reparse point は親ディレクトリも含めて確認し、追わない。通常ファイルのみ読み、開いた後の種別と同一性も確認する。この同一所有者向け機能は、敵対的な別プロセスとのファイルシステム隔離境界ではない。
- `.git`、依存パッケージ、キャッシュ、既知の秘密ファイル名・認証ディレクトリは除外する。名前による除外は秘密情報を網羅的に検知するものではない。ログ・設定本文を API/CLI の結果へ含めず、外部送信しない。結果にはローカルパスが含まれる。
- journal、標準出力、動的な出力先は手動確認が必要として表示する。圧縮ファイル、任意形式の設定、Python/JavaScript の実行による出力先解決は対象外。

`completed` は、この探索範囲と除外規則に従う処理が終わったことを示す。全ディスクや全ログを網羅した意味ではない。読取不能・参照先不明・上限などは `partial` と件数・理由で示す。詳細理由は最大 100 件、集計は全件分を保持する。空のログ・未分類・読取不能を区別し、観測の欠落を正常扱いしない。

CLI は同じ JSON を返し、完了は終了コード 0、一部未探索は 2。入力が不正な場合も 2 で、標準エラーへ説明する。探索だけでは Runtime、データベース、トークンファイルを作成しない。

## 互換性

既存の Source、変換定義、承認、取込方式を変更しない。利用者が候補を選んで登録した後の処理は従来と同じ。新規依存関係・移行・資格情報設定は不要。
